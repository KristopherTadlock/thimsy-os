# thimsy-padd

Merges a device's input nodes into one virtual pad, `Thimsy Gamepad` (bus virtual, vendor
0x5448, product 0x0001), from the `pad` section of `device.json`
(`linux/schema/device.schema.json`). Design: `docs/linux/IMPLEMENTATION.md` F.2, decisions D23,
I12, I13. Installed as `/usr/bin/thimsy-padd`; `S02padd` starts it at boot.

- `src/core/` is pure (no I/O, no clock) and tested on the host: `PadSpec` (device.json),
  `Merger` (remaps, the hat, intercept), `Calibrate` (axis ranges), `Rumble` (force feedback to
  the vibrator node), `Replay` (the trace runner), `InputCodes` (names, generated by
  `tools/gen-input-codes.py` from `linux/input-event-codes.h`).
- `src/io/` is the Linux side: `EvdevSource` (sysfs scan, open, `EVIOCGRAB`, unlink to hide),
  `UinputSink` (`UI_DEV_SETUP`, `UI_ABS_SETUP`, FF upload and erase), `Control`
  (`sys.thimsy.padd.intercept`, `sys.thimsy.padd.ready`, the intercept tap socket).
- `src/main.cpp`: one epoll loop.

Host check (WSL, behind the memory guard):

    nice -n 19 make -C linux/src/thimsy-padd -j1 check

`tests/traces/*.trace` run through `padd-replay` must print their `.golden` file. After a
deliberate change of behaviour, `make golden` rewrites the goldens; review the diff before
committing. The trace format is described in `src/core/Replay.h`.

Not testable on the host: grabbing, hiding by unlink, real uinput and force feedback on a
vibrator (Phase 0 (c), open question 4).
