# Thimsy Base

The Linux image of Thimsy OS for handhelds: a Buildroot external tree
(`BR2_EXTERNAL`, name `THIMSY`) that builds Nano, its services and its
emulators on BusyBox init, an EROFS root and a mainline-based kernel per SoC
family. It follows FlipBase's layout and build (FlipBase arrives here by a
subtree merge, decision D19) and takes each family's kernel patches and device
facts from ROCKNIX (plan section 3).

Status: **skeleton**. The tree, its options, the defconfigs and the build's
entry point exist; the package recipes, init scripts, board files and card
assembly are written by the later steps of `docs/linux/IMPLEMENTATION.md`
section G. Nothing here has been built yet.

## Layout

| Path | What |
|---|---|
| `external.desc`, `external.mk`, `Config.in` | the external tree; `Config.in` also holds the image flavour (release or development) |
| `package/` | one directory per package of IMPLEMENTATION.md E.3: `libthimsy`, `thimsy-nano`, `thimsy-data`, `thimsy-session`, `thimsy-padd`, `thimsy-fonts`, `thimsy-gpu-pack`, `retroarch`, 27 `libretro-<core>`, `ppsspp`, `scummvm` |
| `configs/fragments/*.fragment` | the source of every option, one fact in one place |
| `configs/targets.json` | which fragments make which target, which targets may be published, and the files later steps still owe |
| `configs/thimsy_*_defconfig` | generated by `tools/defconfig.py` and committed, so `make BR2_EXTERNAL=linux thimsy_v8_2_defconfig` works as usual |
| `build.sh` | the entry point: checks, the build guard, source tarballs, Buildroot in Docker |
| `tools/build_guard.sh` | refuses a build while the Android build may be running |
| `tools/defconfig.py` | merges the fragments and checks the tree |
| `tests/` | offline tests, `tests/run.sh` |
| `gpl/` | copyleft and third-party material, under its own licences (`gpl/README.md`) |

## Targets

| Target | Kind | Fragments | Published |
|---|---|---|---|
| `thimsy_v8_0` | tier userland, Cortex-A53 | common, tier-v8_0, userland, gpu-panfrost, gpu-swrast, apps-alpha, dev | no |
| `thimsy_v8_2` | tier userland, Cortex-A55 | common, tier-v8_2, userland, gpu-panfrost, apps-alpha, dev | no |
| `thimsy_v8_0_release`, `thimsy_v8_2_release` | the same, as releases | ... release instead of dev | yes |
| `thimsy_rk3566_hw` | hardware pack, RK3566 | common, hw-common, hw-rk3566, `generated/rk3566/defconfig.fragment` | yes |
| `thimsy_qemu_aarch64_hw` | hardware pack, QEMU virt (tests) | common, hw-common, hw-qemu-aarch64 | no |

A tier is a CPU tier's userland, built with its GPU packs; a hardware pack is a
family's kernel, U-Boot, modules and firmware, built against a tier's SDK
(decision D25). Only release targets may be published (decision I37): no adbd,
no serial getty, SSH off until the user turns it on and then key-only, the root
password locked. `tools/defconfig.py --check` refuses a publishable target that
includes `dev.fragment` or breaks that policy, and `build.sh --publish` refuses a
target not marked `"publish": true`.

## Changing an option

Edit the fragment that owns the fact, then regenerate and check:

```
python3 linux/tools/defconfig.py          # writes configs/thimsy_*_defconfig
python3 linux/tools/defconfig.py --check  # what the tests run
```

A later fragment may change a value an earlier one set only on a line preceded
by `# override: <why>`; any other change is an error. Upstream option names are
checked against a Buildroot tree with `--check --buildroot DIR`.

## Building

```
linux/build.sh --dry-run thimsy_v8_2      # the steps, run nothing
linux/build.sh thimsy_v8_2                # tier: make all sdk
linux/build.sh thimsy_rk3566_hw           # hardware pack, after its SDK tier
linux/build.sh --publish thimsy_v8_2_release
```

Builds run in the `thimsy-linux` WSL2 distro, from a clone on ext4 (never under
`/mnt/c`), with Docker Desktop. `build.sh` first runs `tools/build_guard.sh`,
which refuses while the Android build may be running (the build lock
`/mnt/wsl/thimsy-build.lock`, `MemAvailable` under 9 GB, a `thimsy-*build*`
container, the `thimsy-aosp` distro running, or a load above 8) and holds the
lock for the rest of the run. Then it writes `git archive` tarballs of
`libthimsy/` and `nano/` at `HEAD` (and the exported Nano assets), which the
recipes build from so that `make legal-info` saves them, and runs Buildroot
2026.08.2 in a `debian:trixie-slim` container. Output: `work/linux/images/<target>/`.

## Tests

```
linux/tests/run.sh                        # python3; THIMSY_PYTHON="py -3.12" on Windows
```

The guard's tests need `flock` and run in WSL; they are skipped elsewhere.
